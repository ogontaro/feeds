ゲートではなくガードレール: プラットフォームチームのポリシーを再考する

Gatekeeper や Kyverno の Enforce は「拒否する」ゲートとして設計されがちだが、それをガードレールに作り替えるという設計論。プラットフォームチームがポリシーをどこに置けば開発者の自走を止めずに統制できるか、という IDP を運用する立場に直結する論点を扱っている。Backstage でポータルを出し GitOps でクラスタを同期している構成にとって、ポリシーを「止める仕組み」ではなく「安全に進める仕組み」として設計し直す材料になる。

OperTraitors: Kubernetes Operator の危険な権限昇格経路を暴く新ツール

Kubernetes Operator は広い RBAC を握りがちで、侵害されると権限昇格の踏み台になりうる。その経路を検出する OperTraitors が公開されたという話で、Operator を自作・運用しているなら自分のクラスタの権限設計を見直すきっかけになる。CloudNativePG や Crossplane のように Operator を常用している構成では、マルチテナンシーを考えるうえでも一度は確認しておきたい。

動いている Kubernetes クラスタにも所有権の空白は残る

クラスタが動いていても「誰がそれを所有するか」が曖昧なままだと、変更・障害・コストの判断が止まる。プロビジョニングはできても運営の責任分界が決まっていない、というプラットフォームあるあるを突いた論考。IDP を「作って終わり」にしないための運用設計として読む価値がある。
