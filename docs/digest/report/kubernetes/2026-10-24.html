Kamaji と HAMi で組むマルチテナント GPU Kubernetes

チームごとにクラスタを分けるとコントロールプレーンの分だけコストがかかり、1つのクラスタに相乗りさせると分離が弱くなる、という GPU 基盤のトレードオフに正面から取り組んだ CNCF ブログ。ホステッドコントロールプレーンの Kamaji と GPU 共有の HAMi を組み合わせ、シミュレートしたハードウェア上で検証しているため、実 GPU を用意せずに構成を試せる。GPU を複数チームに開放するかどうかを決める前の設計レビューに効く。

GPU が遊び AI ジョブが待つ状態に、Kubernetes はどう応えるか

GPU に空きがあるのに AI ジョブが割り当て待ちになる、という配分の非効率は、AI 推論を同じクラスタに載せるときに必ず突き当たる問題。KubeCon を前にした連載で、Kubernetes 側がこの問題に新しい仕組みで応じようとしている動きを追っている。自前のクラスタで GPU ワークロードを扱うなら、スケジューリングの前提が変わる可能性として押さえておきたい。
