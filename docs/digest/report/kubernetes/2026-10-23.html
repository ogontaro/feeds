OpenTelemetry、セキュリティ修正のためのバージョニング方針を改定

Stable な SDK と Contrib コンポーネントが、公開 API の互換性を守ったまま、マイナー/パッチリリースで挙動を変えるセキュリティ修正を入れられるよう方針が変わった。自宅クラスタの可観測性を OTel で組んでいるなら、今後は「互換性維持のため入らない修正」ではなく「入る修正」を前提に、アップグレード時の差分確認を組み込んでおきたい。Collector や SDK のバージョン追随をどう運用するかを考える材料になる。

OpenTelemetry Collector で AI エージェントのテレメトリーを絞り込む

AI コーディングエージェントのテレメトリーは量が膨らみやすく、保存コストと読み解きやすさの両面で扱いにくい。Collector のフィルタと加工で必要なシグナルだけを残す方法は、同じ Collector を LGTM スタックに流している構成にそのまま応用できる。可観測性のコスト最適化を進めたい人に実践的な一本。

本番で動く AI エージェントの「持ち主」は誰か

AI エージェントが本番で失敗したとき、誰がオンコールに就き、どの SLO で守るのかという責任分界が決まっていない、という問題を扱う。エージェントを基盤の利用者として扱う流れの中で、アラート・権限・エスカレーションの設計はプラットフォーム側の仕事になる。Backstage や AI SRE の運用に引き寄せて、導入前に決めておく論点を洗い出すのに使える。
