Claude / Claude Code（3 本）

Claude Code に実験的な「Code Mode」— ツール呼び出しを JavaScript のプログラムに変える

Claude Code に、ツールを 1 つずつ呼び出す代わりに JavaScript を書いて複数のツールをプログラムとして束ねる、実験的な Code Mode が入りました。CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1 で有効化でき、長いコマンドの実行中にも応答できます。MCP サーバーをどう設計するか、ツール呼び出しの粒度をどこに置くかを考え直す材料になりますが、実験的機能なので業務で当てにする前に挙動を確かめてください。

worktree だけでは足りない — 並列 Claude Code エージェントの git 分離

並列コーディングエージェントの定番指導は「1 タスク 1 ブランチ 1 worktree」ですが、worktree が分けるのはファイルだけで、ブランチとコミットの格納先はリポジトリで共有されたままです。Claude Code のサンドボックスはどのエージェントにもそこへの書き込みを許すため、あるエージェントが別のエージェントの未 push の作業を消せてしまいます。並列実行の設計やサンドボックスの権限を見直すきっかけになります。

Claude Code のコンテキストはどう組み立てられるか — エージェントループ深掘り(1)

Claude Code のエージェントループが、システムプロンプト・ツール定義・会話履歴・キャッシュをどう組み合わせてコンテキストを組み立てるかを追う連載の初回です。何がコンテキストを消費し、何がキャッシュに乗るのかが分かると、CLAUDE.md やスキルの置き方、コストの見積もりが変わります。内部のラッパーやトークン配分は変わりうるという但し書き付きの概念的な解説なので、その前提で読むのがよいです。

新ツール・サブスク（1 本）

AgentDrive — Conductor のセッションを別のコーディングエージェントで再開する

Conductor は Claude Code と Codex を並列ワークスペースで動かしますが、セッションが持つ計画・行き止まり・変更理由の履歴は、そのセッションを走らせたエージェントしか読めません。AgentDrive はその履歴を同期し、Claude Code で始めたタスクを Codex・Cursor・OpenCode・Antigravity で引き継げるようにする CLI です。エージェントを乗り換えるたびに文脈を説明し直す無駄を減らせます。
