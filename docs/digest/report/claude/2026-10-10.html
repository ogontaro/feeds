2 つの Claude Code セッションが同じ作業コピーを触ると、index まで共有される — 「自分のファイルだけ add」は安全ではない

同じ PC で動かしていたもう 1 つの Claude Code セッションの commit に、まだコミットしていない自分の原稿と図が混ざったまま origin まで届いていた、という実例。作業ツリーだけでなく git index が共有されるため、片方が add した時点で他方の未完了の変更まで巻き込まれ得る、という見落としやすい失敗の型を示している。並列にエージェントを走らせるのが前提になってきた今、worktree などで作業コピーを分ける理由を腹落ちさせておきたい。

「予約機能を作って」は通らない — Claude Code には「やらないこと」と判断基準を渡す

Laravel の雛形をほぼ Claude Code に書かせた中で、予約モジュールだけは粗すぎる指示でも細かすぎる指示でも失敗し、うまくいったのは「やらないことと判断基準を渡す」形だったという記録。実装すべきことを列挙する代わりに、触らせない範囲とトレードオフの決め方を先に渡す、という指示の粒度を自分の CLAUDE.md に当てて測れる。同じ失敗を何度も繰り返している自覚があるなら、先に読む価値がある。
