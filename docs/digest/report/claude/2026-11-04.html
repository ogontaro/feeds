Messages API の message threads で長いエージェントループの待ち時間を削る

会話をサーバー側に保持し、2 回目以降は新しいメッセージと前回の応答 ID だけを送る仕組みが、Messages API のパブリックベータで入った。50 万〜100 万トークンのリクエストでは最初のトークンまでの時間が中央値で約 35% 下がり、多くの Claude Code ユーザーでは既定で有効になっている。トークン使用量と料金は変わらないので、コスト削減ではなく長いセッションの待ち時間を縮める改善として、最後のリクエストから 5 分で切れるスレッドの期限を前提にした設計を確認しておきたい。

Claude Code が pkill -f で自分のシェルを巻き込む exit 144 の罠

pkill -f server.js && node server.js & のように書くと、pkill が自分自身のコマンドラインにも一致してシェルごと終了し、exit 144（ときに 143）で以降が実行されない。while pgrep -f server.js; do sleep 1; done の待ちループも終わらないままだ。開発サーバーの再起動をエージェントに任せたときに踏みやすい罠で、再現条件と 2 分で入る回避策、上流の issue がまとまっている。
