CloudNativePG v1.29.3 / v1.30.1

破壊的変更: なし（ただし 1.29 系は本リリースでサポート終了）
セキュリティ修正が中心。拡張機能パスに .. を含む絶対パス（例 /a/../../../../etc）が Webhook のバリデーションをすり抜け、実行時にマウントポイントの外へ出られてしまう問題を修正し、admission・メジャーアップグレードジョブ・既存の Cluster スペックで一貫して拒否するようにした。gRPC-Go を v1.83.1 に上げ、CVE-2026-84304（HTTP/2 DATA フレーム断片化によるヒープ枯渇）にも対応している。
フェイルオーバー周りの修正も厚く、fencing されたインスタンスが healthy を報告し続けてフェイルオーバーと Pod 再作成が固まる問題、ペンディングのフェイルオーバーが永久に止まる／黙って巻き戻る問題、応答しない旧プライマリの降格待ちを解消。既定の PostgreSQL は 18.6-system-trixie、オペレータ自身のベースイメージも Debian 13 (trixie) になった。
1.29.3 は 1.29.x の最終リリースでサポートは終了するため、1.30 系への移行を推奨。

KEDA v2.21.0

破壊的変更: あり（サービスアカウントトークンの audience 強制、Azure Pipelines の scaleOnInFlight: true 既定化、Temporal の非推奨設定削除の3件）
最重要は CVE-2026-77524 / GHSA-637c-6jxx-4rwm の修正で、サービスアカウントトークンの audience を明示的に強制して TriggerAuthentication の権限昇格を防ぐ。Vault の Kubernetes 認証（operator トークン・既存の projected token・credential.serviceAccountName）や boundServiceAccountToken を使う TriggerAuthentication / ClusterTriggerAuthentication（Metrics API・Prometheus・Loki・Datadog Cluster Agent など）が影響対象なので、アップグレード前に移行ガイドの確認が必要。通常の Vault トークン認証・API キー・OAuth は影響しない。
Azure Pipelines スケーラは割当済みの未完了ジョブもキュー長に数える scaleOnInFlight が既定 true になり、Temporal スケーラは buildId / selectAllActive / selectUnversioned を受け付けなくなった（workerDeploymentName / workerDeploymentBuildId へ移行）。新機能として Azure Cosmos DB Change Feed・ClickHouse・GCP Cloud Spanner のスケーラが追加され、外部スケーラが StreamMetricSpec 経由で HPA のターゲットを動的に更新できるようになった。

Grafana Alloy v1.20.0（helm chart 1.13.0 / v1.20.0-rc.0 を含む）

破壊的変更: あり（OTel コンポーネントの既定値と属性名の変更が多数）
otelcol.processor.k8sattributes が container.image.tag（文字列）ではなく container.image.tags（リスト）を既定で抽出し、pod / namespace / node の既定属性キーが複数形（k8s.pod.labels.）から単数形（k8s.pod.label.）へ変わる。旧挙動に戻す設定はなく、deployment_name_from_replicaset 引数も削除された。
otelcol.processor.transform の Base64Decode は削除（Decode(value, "base64") を使う）、set(target, nil) は実際に nil を設定するようになり、otelcol.receiver.kafka の平文クレデンシャルは SASL/PLAIN に変換される。discovery.hetzner は hcloud ターゲットで __meta_hetzner_datacenter を出力しなくなり、prometheus.exporter.windows は既定の textfile ディレクトリを再び適用する。
Grafana スタックをまとめて動かしている場合は、k8sattributes のラベル名変更がダッシュボードやアラートに波及するため、アップグレード前に確認したい。

Terraform v1.17.0-beta2 / v1.16.4

破壊的変更: なし（ただし terraform version の JSON 出力に format_version フィールドが追加。既存ツールは未知フィールドを無視する想定）
1.17.0-beta2 では provider 要件で変数と locals が使えるようになり、変更のあるリソースだけをリフレッシュする -minimal-refresh 計画オプションが追加された。Terraform Policy が GA となり、plan / apply / query の -policies フラグが実験ビルドや -allow-experimental-features なしで使える（query ポリシーは list ブロックで発見したリソースを評価し、人間可読または JSON で結果を返す）。
安定版 1.16.4 はバグ修正のみで、Terraform Enterprise の旧バージョンでポリシー評価結果の描画に失敗する問題と、Stacks で unknown な count/for_each と deferral が重なったときの誤った deferred エラーを修正している。

Velero v1.18.3 / v1.18.4-rc.1

破壊的変更: なし（restore.velero.io/must-include-additional-items の追加は既存のリストア／プラグインの既定動作を変えない）
1.18.3 は修正と機能追加がまとまって入ったリリース。バックアップのきめ細かいフィルタ（ClusterScopedFilterPolicy / NamespacedFilterPolicy、ラベルセレクタ、PVC の volume mode・access mode マッチ）とリストア側の同機能が追加され、--global-backup-volume-policies-configmap でクラスタ全体のボリュームポリシーを各バックアップにマージできるようになった。
不具合修正では、fs-backup のタイムアウト時に PodVolumeBackup のメタデータが失われて全ボリュームがリストア不能になる問題、restore-wait init コンテナが pod レベルの securityContext を無視して runAsUser 1000 にフォールバックし Init:0/1 でデッドロックする問題、同一ストレージ種別の2つのリポジトリで接続が競合する問題などが修正された。
1.18.4-rc.1 は RC で、デキュー後にパッチ中に完了したバックアップでキューが恒久的に詰まる問題の修正が入っている。
