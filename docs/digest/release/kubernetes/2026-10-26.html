今週のリリース

今週は Go 1.26.10 への追随を通じて、侵害された eMudhra 中間 CA（CVE-2026-111943）の信頼を外すリリースが一斉に出た。TLS 検証が絡む自宅クラスタでは、この一群をまとめて上げるのが最短。

Argo CD v3.6.0-rc3 / v3.6.0-rc4 / v3.5.6 / v3.4.12 / v3.3.17 / v3.3.18

破壊的変更: なし（3.6 系は RC のため本番投入は不可）
stable 系（3.5.6 / 3.4.12 / 3.3.17）は、サーバサイド適用の diff が「他のマネージャに消されたフィールド」を差分として報告し続ける問題の修正が中心。Crossplane や kro のように同じリソースへ書き込むコントローラを併用している場合に効く。加えて SOCKS5 プロキシ経由の SSH リポジトリ取得の復旧、gRPC の SRV（_grpclb._tcp）参照の回避策、sharding で未知クラスタを追加した際の再配分漏れの修正。3.3.18 は eMudhra CA 証明書への security 修正のみで、3.3 系を使っているなら優先度は高い。
3.6 系 RC では Dex の TLS 暗号スイート／曲線設定、reposerver の CMP 失敗後に残る古い manifest とゴルーチンリークの修正、OCI タグリストのキャッシュが入った。

cert-manager v1.21.3

破壊的変更: なし。ただし next private key Secret の扱いが厳格化され、cert-manager.io/next-private-key ラベルと Certificate の所有が必須になる
全ユーザーにアップグレードが推奨されている。侵害された eMudhra のルート証明書を distroless ベースイメージから除去し、Go 1.26.10 で該当チェーンを拒否する。
実務的に効くのは ACME ARI の更新ループ修正。前の証明書の古い ARI ウィンドウが残ると再発行を繰り返し、CA のレートリミットに当たっていた。あわせて、certificates/status を書けるが Secret を読めない主体が任意の Secret を指定して秘密鍵を spec.secretName へコピーさせられる問題を塞いでいる。
Helm chart の http_proxy / https_proxy / no_proxy がクォートされ、*.example.com のような値でも manifest が壊れなくなった。自宅クラスタで no_proxy にワイルドカードを書いている場合はこれが刺さる。

external-dns v0.24.0
