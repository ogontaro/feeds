Argo CD v3.5.3 / v3.4.9（v3.6.0-rc1 も公開）

破壊的変更: なし（3.5.3 / 3.4.9 はパッチ。3.6.0-rc1 は RC のためアップグレードガイドの確認を推奨） 3.5 系と 3.4 系に同一内容のパッチが同時投入された。KubeVirt の停止中 VirtualMachine と suspended な FlinkDeployment のヘルス判定、Crossplane MR がプロビジョニング中に Healthy と誤判定される問題、sync リトライ時の operationState、UI の SSO リダイレクト 401 ループ、GRPCRoute の古い observedGeneration 参照、GrafanaFolder の negative-polarity 条件など、ヘルスチェックと UI の不具合修正が中心。早めの適用を推奨。 3.6.0-rc1 では Kyverno・TLSRoute・AWS ACK・CloudNativePG（Backup / Database）・Velero・Tekton・cert-manager・Prometheus Operator・Flink など多数の組み込みヘルスチェックが追加され、ApplicationSet のプログレッシブシンクがメトリクス化・条件として可視化される。Dex のストレージ種別/TLS 最小バージョンの設定外部化、CNPG Cluster の hibernate/rehydrate アクション、削除メッセージのカスタム化も入る。 リリースを見る

Cilium 1.20.2 / 1.19.8 / 1.18.14

破壊的変更: なし（3 系列同時のメンテナンスパッチ） map events ダンプ時のエージェントクラッシュ、ENI IPAM のプレフィックス委任でサブネットのプレフィックス枯渇時に新規 IP を割り当てられない問題、使用中プレフィックス IP を個別 IP として解放してしまう問題、ENI の IPv6 ルーティング（ヘルスチェック・ingress・IPSec）、GKE 1.36.2 ノードでの node-init 起動失敗、LocalRedirectPolicy の複数リグレッションなど、ENI/GKE 周りの修正が多い。 BGP の defaultGateway ピア自動検出が cilium_host 経由の既定ルートを拾ってしまう問題、HTTPRoute ExternalAuth がバックエンド解決失敗時に fail-open になる問題、SNAT ロードバランス通信の ICMP エラーでチェックサム再計算が抜けていた問題、Hubble Relay が終了処理中も動き続ける問題も修正。 設定面では、これまで受理されながら黙って無視されていた 5 つのオプション（vtep-sync-interval / enable-xt-socket-fallback / eni-delete-on-termination / enableIdentityMark / lb-retry-backoff-max）と Hubble の 4 つの設定ノブが実際に反映されるようになり、Cluster Mesh のサービスバックエンド取り込み時の検証も強化された。 リリースを見る

cert-manager v1.20.4

破壊的変更: なし Go 1.26.6 への更新と依存関係の引き上げで、報告済み脆弱性をまとめて修正（golang.org/x/net の CVE-2026-46600、x/crypto の CVE-2026-56852 / 56854、grpc の CVE-2026-84304 / 84445 / 84303、cel-go、go-pkcs12 など）。あわせて ingress-shim がキャッシュ済みの Ingress / Gateway から applyset ラベルを削除してしまうバグも修正。全ユーザーのアップグレードが推奨される。 x/crypto の SSH 関連 3 件はスキャナが報告し続けるが、cert-manager は SSH 接続を開かず該当関数も呼ばないため 1.20 系では修正されない。クリーンなスキャン結果が必要なら 1.21 へ。 リリースを見る

external-dns v0.23.0 / v0.22.0

破壊的変更: あり（アップグレード手順の確認が必須。最悪の場合 DNS レコードが全削除される） v0.22.0 でアノテーションのデフォルトプレフィックスが external-dns.kubernetes.io/ に変わり、フォールバックがなくなった。既存の external-dns.alpha.kubernetes.io/ アノテーションのままだとレコードが全削除されうるため、アノテーションの移行か --annotation-prefix の明示が必要。--policy もデフォルトなしの必須化。Akamai / Plural / Transip の in-tree プロバイダ削除、Pi-hole v5 API 廃止、Gateway API TLSRoute の v1 移行、AWS の A ALIAS 所有権 TXT の a- プレフィックス化も含む。 v0.23.0 では crd レジストリがソース Namespace に依存しなくなり --crd-registry-namespace の設定が必要。webhook のボディは 32MiB 上限（--webhook-provider-max-body-size）、Gandi プロバイダも削除された。まず --dry-run=true での確認を推奨。 リリースを見る

Backstage v1.55.0（パッチ: v1.54.8 / v1.50.6）

破壊的変更: あり（カタログ API・Elasticsearch 8 必須化・BUI ルーティング・TechDocs の MkDocs プラグイン許可リスト） catalog-backend の非推奨機能が削除された。catalog.enableRelationsCompatibility と互換レイヤ、CodeOwnersProcessor / AnnotateScmSlugEntityProcessor、catalog.stitchingStrategy.mode がなくなり、relations は targetRef のみになる。 Elasticsearch クライアントが v8 に上がり Elasticsearch 8.19 以上が必須（7.x は非対応）。ElasticSearchClientWrapper の戻り値が body / statusCode / headers / warnings を持つ正規化レスポンスに変わり、生のクライアント型や meta を参照するコードは修正が必要。 BUI のリンクがホストアプリのルーターを使うようになり、ButtonLink や Link などの render prop が削除された。TechDocs は許可リスト外の MkDocs プラグインを警告つきで除去するため、必要なものは dangerouslyAllowAdditionalPlugins に追加する。段取りを踏んでの移行が必要な更新。パッチ側は MkDocs プラグイン設定と Sentry API 設定の検証改善。 リリースを見る

HolmesGPT 0.42.0

破壊的変更: あり（kubernetes-remediation のファイル読み取り許可パスの既定値が変更） セキュリティ修正が主眼。kubernetes-remediation MCP の fileReadAllowedPaths の既定が / だったため、自動承認される read_file_from_container 経由で Pod 内の任意ファイル（クラウド資格情報や .env、TLS 鍵など）が読めてしまっていた。既定が限定パス群に狭められ、fileReadRequireCanonicalization で readlink -f 解決を必須にできるようになった。 ただしチャートが固定するイメージは 1.2.0 のままで、canonicalization と拡張された拒否リストを効かせるには 1.4.0 以降へのイメージ更新が別途必要（1.3.0 には GPU 診断ツールが入る）。あわせて MCP の structuredContent 対応、New Relic ツールセットのタイムアウト設定、namespaceScopedRBAC の Helm 値が追加された。 リリースを見る
