Argo CD v3.3.15・v3.4.10・v3.5.4 / v3.6.0-rc2

破壊的変更: Kustomize で Helm チャートをレンダリングするビルドが helmGlobals.configHome を参照しなくなりました（通常の http / https / oci チャートリポジトリはそのまま動きますが、そのディレクトリから登録した Helm プラグインに依存していたビルドは動きません）。4 MiB を超える OCI マニフェストは拒否されます。3.6 系はアップグレードガイドに server-side diff が既定になる旨が追記されています。

今週は 3.3 / 3.4 / 3.5 / 3.6 の各ラインに同時にセキュリティ修正が入りました。CRITICAL 4 件はいずれも repo-server を踏み台にできる経路で、Kustomize の remote ref が repo-server 上でコマンドを実行できる問題（GHSA-9v9p-x54c-58gc）、Kustomize の Helm config home 経由のコマンド実行（GHSA-fw5c-w8rc-j7fx）、Jsonnet の import が repo-server のファイルを読める問題（GHSA-m3vr-7329-44ww）、PreDelete / PostDelete フックで AppProject の制約を回避できる問題（CVE-2026-77459）です。HIGH はログイン失敗のレート制限が並行リクエストで回避できる問題（CVE-2025-61560）と、SSH の Git リポジトリでリポジトリプロキシ URL 経由のコマンド注入（CVE-2026-55797）。
自宅クラスタの同期を Argo CD に任せているなら、リポジトリの内容が repo-server 上のコード実行に至る経路が塞がれたことになるので、使っているライン（3.5.4 など）へ早めに上げる価値があります。修正では repo-server のヘルスチェックタイムアウトによる CrashLoopBackOff（3.5.4）、manifest-generate-paths のキャッシュミス時の誤検知（3.5.4）、KubeVirt / FlinkDeployment / Crossplane MR / Cluster API Cluster の health 判定（3.3.15）も入っています。
機能面はログイン試行時にユーザー名をログに出す変更（3.3〜3.5）と、argocd login で使ったクライアント証明書を保存・再利用する変更（3.6）です。3.6.0-rc2 は RC なので、3.6 系は GA を待つ判断で問題ありません。

dex v2.46.0

破壊的変更: 明示の宣言はありませんが、未知の設定フィールドを拒否するようになり（Disallow unknown config fields）、セッション Cookie が protobuf 化・暗号化されました。効かないキーが設定に残っていると起動しなくなる可能性があるため、アップグレード前に設定を検証してください。Cookie 形式が変わるので既存セッションは再ログインになる見込みです。

認証基盤をまとめて近代化した大きめのリリースです。2FA（TOTP）と WebAuthn、Kerberos コネクタ、SAML のリフレッシュトークン、OAuth2 の client credentials フロー（opt-in フラグ）、PKCE の設定、ID-JAG（requested_token_type）対応、Cookie 暗号化、OIDC の RP-Initiated logout が入りました。内部では AuthSession を導入してトークン発行を issuer 抽象に移し、リフレッシュトークンのライフサイクルを dex 側が持つようになり、CEL コンパイラによるポリシー評価と gRPC のセッション API も追加されています。Argo CD の SSO に dex を使っているなら、2FA / WebAuthn がそのまま使えるようになるのが実務上の目玉です。

external-secrets v2.12.0

破壊的変更: v2.11 系で入っていた imageRegistry の破壊的変更が revert されました（#6996）。チャートで imageRegistry を上書きしている場合は値の解釈が元に戻るので差分を確認してください。あわせて、エラーメッセージ内でテンプレート文字列を評価しない修正とテンプレートからの fail 削除が入っており、テンプレートの挙動が変わります。

Password ジェネレータに prefix / suffix が付き、Conjur の Cloud Authenticator、チャートの rbac.leaderElection.create トグル、replicas が 2 以上なのに leader election が無効なときの警告が入りました。Secret を書き込む前のバリデーション、Akeyless / AWS ACM で「存在しない」を NoSecretErr として返す修正、Pulumi の PushSecret で environment 定義を保持する修正もあります。シークレットの外部管理を担うコンポーネントなので、テンプレート挙動の変更は適用前に検証しておくのが安全です。
