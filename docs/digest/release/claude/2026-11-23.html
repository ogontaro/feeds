Claude Code v2.1.326–v2.1.330

破壊的変更: なし。ただし v2.1.328 で Amazon Bedrock・Google Cloud の Agent Platform・Microsoft Foundry・Claude apps gateway 上の Opus 4.6 / Sonnet 4.6 に auto モードが追加され、権限モードを指定しない対話セッションは auto で開始する。第三者ゲートウェイ経由で権限境界を前提にしている場合は既定の変化を確認したい。同じ v2.1.328 で zsh の =cmd がコマンドのパスに展開されなくなり、v2.1.326 からは設定ファイルの 64 段より深いネスト値が警告付きで捨てられる。
v2.1.330 で Anthropic の Enterprise Admin Console 管理組織へのサインインに対応し、組織の設定とクラウドプロバイダー／ゲートウェイが適用される。組み込み mod の easel が Pro / Max（対応環境では Team / Enterprise）の macOS・Linux で有効になり、MCP のメトリクス結果の下などに自動でグラフを描く（/config で自動描画をオフにできる）。v2.1.326〜327 では Code Mode と agent teams の併用、claude mcp add-json - による stdin からのトークン入力（セッション内では不可）、/status での壊れた agent / skill / command ファイルや一致しない hook matcher の一覧表示が入った。
修正は並行実行と長時間セッションに効くものが中心。別の Claude Code セッションが作業中の worktree を ExitWorktree が削除する問題、複数プロセスが同時に設定を保存すると変更が消える問題、MCP ツールの input schema が原因でセッションファイルが数 MB 膨らみターンが失敗する問題、長時間会話の compact 直後に数分フリーズする問題、WebFetch がセッションごと固まる問題、~/.claude.json が既定値に戻る問題、Code Mode の暴走ループがメモリを食い尽くす問題を修正した。
hooks の宣言場所を trust dialog に出す変更や /tasks への /loop wakeup・fork の表示も入り、権限・ツール・指示を配布物として管理する流れがさらに進んでいる。

opencode v2.3.1–v2.3.2 / v1.19.6 / process-daemon v0.6.0

破壊的変更: v2.3.1 で foreground の timeout: 0 が「コマンド終了まで待つ」から既定の 120 秒に変わり、shell_timeout_background と experimental.background_compaction は廃止（設定は読み込まれるが無視される）。v1.19.6 は OpenCode 1 から 2.0 へのアップグレードを案内し、OpenCode 1 向けのプラグインは更新が必要。2.0 本体はバックグラウンドでダウンロードされ、再起動時・終了時・後で、を選んでインストールする方式で、セッション・プロジェクト・設定は保持される。
v2.3.2 の目玉は GPT-6.2 のプロンプトキャッシュ修正。Responses の instructions フィールドに送っていた system prompt が毎ステップ非キャッシュ入力として再課金されていたのを、先頭の developer メッセージとして送ることで 2 ステップ目以降キャッシュさせる。GitHub Copilot の gpt-6.2-sol では 1 ステップあたりの非キャッシュ入力が約 14,000 トークンから 3 トークンに減り、/responses/compact 経由の圧縮も同じキャッシュ済みプレフィックスを読む。
v2.3.1 ではタイムアウトしたシェルコマンドが kill されずバックグラウンドに移って完走するようになり、長時間のビルドやテストに向く。バックグラウンド compaction が既定オン（compaction.background: false で無効。使われなかった要約もトークンを消費する）、ChatGPT サインインで GPT 6.2 Sol / Astra を選択可能、AGENTS.md が無いディレクトリでは CLAUDE.md を読む挙動が復活（OPENCODE_DISABLE_CLAUDE_CODE で抑止）、実験的 schedules が automations に改名された。
v1.19.6 は画像が多いセッションで履歴が 25 MiB を超えると古い画像をプレースホルダーに置き換える。process-daemon v0.6.0 は @opencode/pty 0.6.0（protocol 9）の公開のみ。

Orca 1.4.263–1.4.271 / Android 0.0.68

破壊的変更: なし。ただし Orca Bots はベータで、デスクトップを更新してもスマホ側の機能は入らず、対応するモバイルビルドが必要。1.4.271 の既知の問題として、アプリ再起動後や使用量上限エラー後にボットが作業を途中で止めることがあり、次版で修正予定と明記されている。
今週の中心は Orca Bots の対応エージェント拡大。1.4.268 で Cursor・GitHub Copilot・Hermes、1.4.269 で Kiro・Kimi Code・Auggie・Gemini CLI・Kilo Code・MiMo Code・Droid・Goose、1.4.271 で Qwen Code が加わり、ペアリングした複数コンピュータのボットを 1 つのグループに混在させられるようになった。グループ rooms では応答中の @name が次のターンをそのメンバーに渡す。
