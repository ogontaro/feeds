Claude Code releases v2.1.290〜v2.1.296

破壊的変更: なし（追加と修正のみ）。ただし v2.1.291 は v2.1.290（クラウドセッションで許可プロンプトへの回答が落ちる）と v2.1.288（終了時に最後のメッセージが失われる）の回帰修正なので、この範囲を使うなら最新まで上げてください。

5 日間で 7 版。目玉は Haiku 5.5（claude-haiku-5-5）が Anthropic API の既定 Haiku モデルになり、1M context で $0.10/$0.50 per Mtok（100K 超のプロンプトは $0.50/$2.50）になったことです。軽い処理やサブエージェントを Haiku に逃がす判断が、値段の面で現実的になりました。
権限境界とサンドボックスまわりが厚い週です。コマンド / HTTP フックに onFailure: "block"（起動失敗・タイムアウト・想定外の終了コードでアクションを止める）が入り、マネージド設定の PreToolUse フックが "continue": false で拒否できるよう修正されました。プロンプト指示型フックが塞ぐべき操作を通していた問題（v2.1.294）も直っています。セキュリティでは、PreToolUse の承認と auto モードがネットワーク（UNC）パスからの読み取りで許可プロンプトを迂回していた問題、macOS / Windows で読み取り中に差し替えたリンクが承認範囲外のファイルを返せる問題、改ざんされた server-managed settings のキャッシュがポリシープラグインを外せる問題、sandbox の read-deny パスがセッション途中で差し替わってもプロジェクト許可が残る問題などを修正しました。
複数エージェントの並行実行と協調では、サブエージェントに autoCompactWindow（親より早く自動圧縮）、Agent ツールに effort パラメータ、CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL が入りました。LLM ゲートウェイ向けには、upstream ごとの許可モデル一覧、timeouts.upstream_ttfb_ms、upstream_request_id の監査イベント、forceLoginMethod: "gateway" のユーザー設定対応、context-1m beta を拒否するゲートウェイでの再送が入っています。MCP は切断後の再接続バックオフ（最大 30 秒）と重複ページングカーソルの修正、Read ツールの allow_large、ターミナルに作業状態を出せる OSC 7501（Program Status Protocol）も入りました。

Orca releases v1.4.221〜v1.4.224

破壊的変更: 更新すると新しいターミナルバックグラウンドサービスが起動し、既に開いていたターミナルは旧サービスのまま動き続けます（この版の端末関連の修正は、更新後に開いたターミナルにだけ効きます）。Windows の Codex は Orca 管理下のフォルダではなく自分の ~/.codex を使うようになり、Orca 内だけで追加した MCP サーバーは再追加が必要です。v1.4.217 以前から直接 v1.4.223 以降へ上げると、以前のネイティブチャットが表示されません（ファイルはディスクに残ります）。v1.4.221 にはセキュリティ修正が含まれ、フォルダを信頼済みにした際に ~/.copilot/config.json が同一マシンの他ユーザーから読める状態になる問題（Copilot のログイントークンが入り得る）が直りました。

自動化（Automations）の実行ごとにエージェントのモデルと effort を指定できるようになりました。Automation エディタの Advanced の「Extra agent arguments」（または --extra-agent-args）に -model haiku --effort high のように書き、Claude / Codex / Grok / CodeBuddy はモデルと effort、Cursor はモデル、OMP はモデルに対応します。各実行は新しいセッションで始まり、他の自動化はホストの既定を保ちます。
SSH ホストは Orca 自身のランタイムを配る managed Orca server で動くようになり、ホストの Node のバージョンやビルドツール不足で接続に失敗しなくなりました。ネイティブチャット（実験的）は OpenCode（2.x を含む）・Pi・OMP が構造化チャットで開き、返信の中にグラフ・図・モックアップを描けます。
使用量メニューに Claude の usage credits、OpenCode Zen の残高、Codex のクレジットが使用上限と並んで出るようになり、サブスクの残量確認が 1 か所で済みます。ほか、大きい CSV の編集、1 ワークスペースへの複数 PR / MR の紐付け、日本語・中国語・韓国語入力で Enter 確定がフィールド送信を兼ねてしまう問題の修正など。

Codex CLI releases 0.162.0・0.162.1 / 0.163.0-alpha.1〜alpha.6

破壊的変更: なし（0.163.0 系は alpha）。0.162.1 は、非同期の質問が複数行のときに TUI が落ちる問題と、起動中の background server と CLI 既定の機能設定の差で起動に失敗する問題を修正しています。

0.162.0 で、信頼したローカルプロジェクトから managed Git worktree を作成・一覧するツールが入りました（worktrees 機能を有効にした場合）。複数のエージェントを並行で走らせて作業を分けるときの土台になる変更です。Command Center でのタスクの pin（p）、/copy でのトランスクリプトのブロック単位のコピー、承認ヘッダーや質問・MCP プロンプト・警告内の URL のクリック対応も入っています。

修正は、CRLF を保つ apply_patch、Linux sandbox の複数 deny ファイル、Windows 10 のドライブレターのファイルアクセス、Retry-After の尊重、Responses / WebSocket の再試行など。Windows 向けに署名済み PowerShell インストーラも公開されました。
