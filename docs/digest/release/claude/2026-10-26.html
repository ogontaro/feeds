Claude Code releases v2.1.304〜v2.1.310

破壊的変更: 明示的な破壊的変更はありません。ただしアップグレード時の注意が3つ。v2.1.304 は tool search を拒否するゲートウェイ／プロバイダー配下で全リクエストが失敗する回帰を含み、v2.1.305 で修正されています（v2.1.304 に固定しているなら上げてください）。v2.1.305 から allowedMcpServers の挙動が変わり、managed-mcp.json の stdio サーバーのうち env にだけ ${VAR} を使うものが許可リストで除外されなくなりました。許可リストから漏れていたサーバーがアップグレード後に読み込まれるので、止めたいものは deniedMcpServers に書く必要があります。v2.1.309 からは、サイズ上限を超えたネストした CLAUDE.md が先頭だけを読み込むようになりました。

5日間で7版（10/19〜10/23）。今週の中心は v2.1.309 の権限・サンドボックス修正です。サンドボックス化された Bash が各コマンドの前にシェルの起動ファイルをサンドボックス外で読んでいた問題、macOS の denyWrite glob がシンボリックリンク経由の実パスに効かない問題、サンドボックス化されたコマンドや auto-accept された編集が --mcp-config で渡したファイルを書き換えられる問題、無効化した MCP サーバーが後続の許可プロンプトで再接続される問題、Edit(path) の拒否ルールがサブシェルを含む Bash リダイレクトを塞げない問題、worktree 分離ガードがロケール接頭辞付きコマンドや zsh の算術コマンドで抜けられる問題などをまとめて塞いでいます。v2.1.310 も、ファイル読み取りの許可プロンプトがシンボリックリンクの行き先を表示しない問題と、Git Bash が無い Windows で引用符だけのフックコマンドがツール呼び出しを通してしまう問題を修正しました。v2.1.305 で追加された sandbox.allowNestedUserNamespaces は、Linux で Chromium や rootless podman を動かすための設定ですが、サンドボックスのファイル保護を抜けられる方向のスイッチでもあるので、有効化は用途を絞って判断したいところです。ランドスケープの「エージェントの権限境界とサンドボックス」がそのまま効いてくる範囲です。

運用面の目玉は v2.1.310 の Monitor ツール（Bedrock / Vertex / Foundry や、テレメトリ・非必須通信を無効にした環境でも利用でき、長時間のフォアグラウンド sleep もそこでブロックされる）と、v2.1.307 の OpenTelemetry イベント claude_code.safety_event（許可ルール・auto モード・安全チェック・フック・サンドボックスが、ツール呼び出しを止めた／確認した／差し戻したことを1件ずつ記録）です。OpenTelemetry / LGTM で回している監視に、エージェントの拒否・承認の判断をそのまま流せるようになります。v2.1.307 の /claude-api api-version、v2.1.304 の /auto-mode-setup（プロジェクトと直近セッションを読んで auto モードに環境を教える）と /claude-api managed-agents-secure（Managed Agents の設定を Anthropic のセキュリティガイドと比較）も、権限設計を運用に落とす道具です。クラウドセッションと Remote Control は Enterprise のカスタムロールで権限を分けられるようになり、クラウド環境のセットアップスクリプトをファイルから読み込めるようになりました。

複数エージェントまわりでは、v2.1.309 が split-pane の teammate に leader の --tools と deny ルールを継承させ、v2.1.307 が同時起動した fork サブエージェントに「どれが自分の起動か」を伝えるようにしました。地味に効くのは、巨大なネスト CLAUDE.md を読んだ後に compaction を繰り返す問題、Prompt is too long 後の base64 / SVG のような濃いテキストで次のリクエストも失敗する問題、cleanupPeriodDays を非常に大きくすると貼り付けた画像などの新しいファイルを掃除が消してしまう問題の修正です。MCP は接続が切れた HTTP ツール呼び出しの二重送信を止め、再試行を読み取り専用・冪等なツールだけに限定しました。

破壊的変更: なし（0.163.0 系は alpha）。ただし 0.164.0 で resume が保存済みのスレッド設定を復元するようになり、グローバル既定で上書きしなくなりました（会話ごとの model / effort が残る）。Amazon Bedrock のセットアップウィザードは既定で有効になります。

修正は、compaction 失敗時に部分要約を履歴に残さない、背景 compaction の失敗で panic しない、Windows の HTTPS / WebSocket で Negotiate / NTLM によるプロキシ認証、複数階層の -c / --config の保持、キューしたプロンプトが権限選択の解決を待つ、macOS の大小文字違いメタデータパスと実行ファイル探索の差し替え可能なシンボリックリンクに対する sandbox 検査の強化など。未使用インストールの整理、放棄された marketplace checkout の掃除、デーモンログの上限によるディスク使用量の削減も入っています。

ランドスケープに Codex の項目はありませんが、/permissions のインライン指定と sandbox 検査の強化は、Claude Code 側の --tools / deny ルールやサンドボックス設計を比べる材料になります。0.163.0-alpha.11.1〜0.164.0-alpha.12 の alpha はノートがなく、実質は 0.164.0 を見れば十分です。
