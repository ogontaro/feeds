mise 2026.11.12

破壊的変更: なし
mise audit が追加され、設定中のツールのバージョンを OSV.dev のアドバイザリと突き合わせて一覧表示する。脆弱性があれば終了コード 1 を返すので CI のゲートにそのまま使え、--json で機械可読な出力も得られる。mise upgrade --vulnerable は既知の脆弱性があるツールだけを更新し、--bump を付けない限り設定レンジ内に留まる。
mise prune --system が root 所有のシステムインストール領域の不要バージョンを sudo 経由で削除する。mise upgrade もアップグレード後にシステムインストールの旧版を upgrade.prune_after の猶予後に掃除するようになり、これまで無限に溜まっていた旧バージョンが残らなくなった。
ツール単位の bump = false で mise upgrade --bump / mise outdated --bump の対象から外せる。topgrade のように mise upgrade を代行するツールが mise.toml のエントリを書き換えてしまうのを防げるので、自宅の mise 管理ツールはこれで固定するとよい。ほかにドットファイルグループの root 省略時の既定値変更、mise reshim --system の修正など。

Docker Engine 29.10.0

破壊的変更: insecure-registries を明示した構成では、ループバックアドレス(127.0.0.0/8、::1/128)が自動的に insecure 扱いされなくなった。daemon.json に insecure-registries を書いている場合、HTTP や自己署名証明書のローカルレジストリ(localhost:5000 など)への push/pull が失敗しうるので、必要なアドレスを明示的に追加するか TLS を設定する。"insecure-registries": [] は既定の insecure レジストリをすべて無効化する。
Engine API の仕様書が OpenAPI 3.2 に移行し、Swagger 2.0 は当面生成物として併設されるが、今後の API バージョンでは per-version の Swagger 2.0 コピーは出なくなる。ツール側が古い仕様ファイルを読んでいる場合は要更新。
実験的拡張として、デーモンが直接管理するワンショット/ cron ジョブ(--enable-extension org.mobyproject.jobs.v0)が追加され、/etc/docker/containerd.d/ で組み込み containerd を設定ファイルでカスタマイズできるようになった。ローカル開発クラスタで「cron のためだけに別スケジューラを立てる」必要がなくなる可能性がある。AlmaLinux / Oracle Linux / Rocky Linux 向けパッケージも追加。v2.0.0-beta.31(ベータ)も同時期に出ているが、内容の記載はなし。

Devbox 0.22.0

破壊的変更: 隠しコマンド devbox log(shell-ready / time-to-interactive のテレメトリ)が削除され、代替はない。2024 年半ば以降発火していなかった .envrc の古い警告と DEVBOX_NO_ENVRC_UPDATE も削除された。
性能改善が中心で、lockfile に無いパッケージの並列解決、nix path-info のバッチ化と nixpkgs のプリフェッチ 1 回化、devbox update の並列化(変更のあったパッケージだけ再計算)、環境計算時の runx / script / state-hash の重複処理の削減により、install・update・shell 起動が速くなった。
NIX_SSL_CERT_FILE / SSL_CERT_FILE を自分で設定している場合(社内プロキシ環境など)、nss-cacert を引くパッケージの追加時に上書きされなくなった。0.21.0 で壊れていた Devbox Docker イメージのビルドも修正。devbox global の shell 起動が速くなるので、常用していれば上げる価値がある。

uv 0.13.9

破壊的変更: なし(ソースからビルドする場合のみ、最低 Rust バージョンが 1.98 に上がる)
プレビュー機能として PEP 832 の .venv リダイレクトファイルをプロジェクト環境でサポート。.venv を実体へのポインタにできるため、ビルドキャッシュやエージェント用サンドボックスで仮想環境を共有しやすくなる。HTTP/2 の keep-alive プレビュー機能(http2-keep-alive)は応答の無いコネクションを閉じる。
環境マーカーの繰り返し条件をくくり出すことで lockfile が小さくなり、読み込みも高速化。インデックスが別パッケージ名で広告した wheel を拒否する修正、uv lock --locked が等価だが表記の違うプラットフォームマーカーを拒否していた問題の修正、アポストロフィを含むマーカー値の引用の修正が入っている。

GitHub CLI 2.105.0

破壊的変更: なし
gh event コマンド群(プレビュー)が追加され、PR のレビュー投稿やチェックスイート完了などのイベントを GitHub Event Streams 経由で待ち受けられるようになった。gh event listen --resource <PR URL> --event com.github.pull_request.review.submitted.v1 のように指定すると、ポーリングせずに最初のイベントで終了する(--count で複数、--follow で継続)。イベントは CloudEvent JSON で出力され、--jq でそのまま絞り込める。
エージェントに「PR のレビューが付くまで待つ」を指示するとき、これまで gh pr view を回すしかなかったのがイベント購読に置き換わる。gh pr / gh api 利用時に gh event listen を提案する仕組みも入っており、コーディングエージェントの待ち合わせ手段として素直に adoption しやすい。Event Streams 自体はプレビューでウェイトリスト制。
