mise v2026.10.6〜v2026.10.8

破壊的変更: なし。既定で有効になる挙動が 3 つあります（インストール先の global リンク、プロンプトでのバックグラウンド自動更新、ダウンロードの検証付きキャッシュ）。いずれも無効化する設定はありませんが、既存の mise.toml や lockfile を書き換える必要はありません。

~/.local/share/mise/installs/<tool>/global が常に作られ、mise use -g に追随するようになりました。IDE など mise を経由できないツールに、バージョン切替で変わらないパスを渡せます（global 設定が無いツールではリンクが消えるだけ）。宣言化した環境をエディタから使うときの定番の悩みが消える変更です。
auto_update がシェルプロンプトでも走るようになりました。mise activate 環境では shim を通らないため更新されなかったのが、hook-env がデタッチしたバックグラウンドプロセスで更新します（プロンプトは待ちません）。tool_update.global_auto で global の全ツールを一括で対象にでき、mise upgrade --global / mise outdated --global はプロジェクトの固定を無視して global / system 設定だけを上げます。ダウンロードは content-addressed な検証付きキャッシュ（$MISE_CACHE_DIR/downloads-cas、既定 2GiB、LRU 削除）に入り、checksum 固定のツールはネットワークに出ずキャッシュをハードリンクするので、CI では ~/.cache/mise/downloads-cas をキャッシュする運用に変わります。コーディングエージェントなど自己更新するツールを mise 経由で更新させる "Self-updating tools" のドキュメントも追加されました。
10.6 では [vars] に prompt を書くとマシンごとに 1 回だけ聞いて $MISE_STATE_DIR/vars.toml（dotfiles 履歴の外）に保存でき、include がローカルの TOML も読めるようになりました。mise run --affected が未コミットの作業ツリーも数えて experimental が外れ、dotfiles 履歴の修正（mise dot save --re-encrypt、mise dot status の未保存表示）も入っています。vfox / mise-util / mise-settings は同日付の内部パッケージ更新のみです。

uv 0.13.0（ほか 0.12.24）

破壊的変更: 複数あります。既定の安定版 Python が 3.14 から 3.15 に変わり、-c で読み込む constraints ファイルの --require-hashes を尊重するようになったためハッシュ欠落の install は失敗します（オプトアウト不可）。Windows ARM64 では native aarch64 のインタプリタを優先します（UV_PYTHON_ARCH=x86_64 で従来動作）。included constraints 内の editable 要件（-e）は pip と同じくエラーになり、Python 3.10 以降では distutils 起動パッチを入れなくなりました（既存 venv は自動では変わらないので作り直しが必要）。requirement ファイルのオプション値は単一パス扱いになり、uv_build に上限を切っている場合は <0.14 に緩める必要があります。

キャッシュの形式も変わるため、アップグレード後に依存の再ダウンロードや再ビルドが起きます（複数バージョンの uv でキャッシュを共有するのは引き続き安全）。ビルドバックエンドの設定に破壊的変更はありません。0.12.24 はバグ修正と性能改善が中心で、uv cache prune が孤立した一時ビルド環境を消すようになり、UV_NO_CACHE=false / UV_OFFLINE=false のように環境変数で設定を上書きできる箇所が増えています。

Bun v1.4.3

破壊的変更: 明示の宣言はありませんが、Node 互換に寄せる挙動変更が複数あります。(a?.b)(x) は a が null / undefined のとき TypeError、BigInt("-") などは SyntaxError、net.Socket#write() は即時失敗時に false を返して socket.errored を立て、util.format('%s', Buffer|URL) は toString() を使います。jsx = "solid" はエラーになり、ルート証明書が NSS 3.128 に更新されて Entrust など一部 CA が外れました。

目玉は組み込みの TypeScript 型チェッカー bun check です。typescript-go 由来で TypeScript 7.0.2 の適合テスト 51,210 件を全通過し、16 コアで tsc より 3〜6.4 倍速くメモリは 2.2〜4.9 倍少ないという結果が出ています（emit も LSP も無く、型チェック専用）。Bun.FetchSession で TLS・プロキシ・keep-alive をグループ単位で持ち回せ、NO_PROXY のワイルドカードや CIDR にも対応しました。Bun.ModuleGraph（実験的）は 1 プロセス内でアプリの複数インスタンスをモジュール状態ごと分離して動かせます（サンドボックスではない点に注意）。セキュリティ面では TLS サーバ検証をハンドシェイク中に実施するようになり、HTTP/2 の stream reset がレート制限されます（CVE-2023-44487 ほか）。--disallow-code-generation-from-strings が実際に eval() を止めるようになったのも、エージェント実行環境の隔離としては効きます。

Docker Engine v29.9.0（ほか client/v0.6.2、v2.0.0-beta.26・.27）

破壊的変更: 明示の宣言はありません。ただし containerd イメージストアで remote snapshotter（nydus / overlaybd / soci / stargz）を使っている場合、docker pull がスナップショッタ側にあるレイヤのダウンロードを省略する lazy-pull が既定で有効になります（lazy-pull デーモン機能で制御可）。

Go ランタイム 1.26.9 と golang.org/x/net 0.60.0 への更新で、HTTP/2 クライアントによるデーモンのクラッシュ・メモリ枯渇・接続レベルフロー制御の回避・CPU 消費（CVE-2026-97032 / 78659 / 78663 / 78669）と、Windows でデータルート外にディレクトリを作られる問題（CVE-2026-56857）が修正されました。デーモンを上げる価値が高い回です。加えて、remote snapshotter 利用時に必要なレイヤを取りこぼして export / push だけ壊れる不具合、rootless の RootlessKit API ソケットリーク、overlay 暗号化ネットワークの一部トラフィックが平文で出る不具合（受信側が破棄するため片方向に限られる）、ルーティングゲートウェイモードで published port が docker ps に出ない問題が修正されています。BuildKit は v0.34.0、containerd は v2.4.1 に更新。Go SDK の client/v0.6.2 は HTTP upgrade ハンドシェイク中のリクエストキャンセルとデッドラインを修正しています。

fzf 0.74.5

破壊的変更: なし。

セキュリティ修正が 2 件入っています。fzf-tmux が -l50 のようなレイアウトサイズを bash の算術式として評価していた問題（任意コマンド実行や tmux フラグ注入が可能、GHSA-w6x2-f5m4-xw82）と、zsh 補完が予測可能な /tmp パスに FIFO を作っていた問題（GHSA-7rj6-7pqx-v7rm）です。ターミナルから気軽に呼ぶツールなので、これは早めに上げる理由になります。機能面では、tmux 3.8 以降で zoomed pane 上の --popup が zoom を解除しなくなったほか、--gap-line が grapheme cluster を切る問題、fzf が解釈しないエスケープシーケンスの残りがクエリに混ざる問題、reload 後の focus イベントが発火しない問題が修正されています。

lazygit v0.66.0・v0.66.1

破壊的変更: なし。ただし 0.66.0 でステージング操作の UI 自体が変わり、カスタム diff レンダラを使っている場合は新しい OSC プロトコル対応版（delta / diff-so-fancy の最新）への更新が必要です。

メンテナ交代後で最大のリリースです。独立したステージングパネルが廃止され、メインビュー上で hunk や行を選んで space で stage、d で discard、e でエディタ、n / N でファイル移動、<ctrl-g> でファイル一覧からジャンプ、という操作体系になり、設定した diff レンダラの出力がそのまま使われます。スタックブランチは最上位を push / pull すると残りもまとめて扱えるようになり、diverge が自分の rebase 起因か他人の rebase 起因かを色で見分けられるようになりました。ターミナルの背景色に応じたダーク / ライトテーマの切替と、コミットグラフの描画文字の改善も入っています。0.66.1 はその回帰修正（diff.mnemonic 有効時の hunk ステージ、検索ハイライト、gui.wrapLinesInDiffView オフ時の横スクロールなど）です。
