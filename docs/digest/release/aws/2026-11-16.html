Karpenter v1.15.2

破壊的変更: なし(API・設定の変更なし)。ただしコントローラがクラッシュループする既知の問題あり
DRA(動的リソース割り当て)のインスタンスタイプメタデータだけを更新したリリースで、settings.awsFeatureGates.draNVIDIAGPU / draEFA(または settings.enableDRA)を有効にしていなければ挙動は変わらない。g7/g7e の NVIDIA GPU DRA メタデータを追加し、EFA DRA の対象を 29 から 302 インスタンスタイプへ拡大(追加分は dra.net/pciDevice / pciVendor / rdma のみを設定するため、pciSubsystem や numaNode、pcieRoot で選択する claim には一致しない)。既知の問題として、AMI エイリアスに @ が 2 つ含まれる EC2NodeClass(例 al2023@latest@foo)が検証を通ってしまいコントローラをクラッシュループさせ、全 NodePool のプロビジョニングが停止する(該当 EC2NodeClass を削除すれば復旧、#9800 / 修正 #9801)。GPU・EFA を使わない構成ならアップグレードの実利は薄いが、EKS のノード調達を Karpenter に任せているなら AMI エイリアスの書き方だけは先に確認しておきたい。ソースからビルドする場合は Go 1.26.11 以上が必要。

aws-load-balancer-controller v3.6.3

破壊的変更: なし(CRD 更新不要、コントローラのアップグレードのみで完結)。v3.6.0 より前から上げる場合は v3.6.0 の CRD 手順を先に適用する
Go 1.27.4 と golang.org/x/net v0.62.0 への更新、EKS-D minimal ベースイメージ(2026-11-10 版)への再ビルドによるセキュリティ修正が主で、動作や設定の変更はない。Helm chart に Service webhook の matchConditions 対応が入り、object.spec.type == 'LoadBalancer' のような条件で webhook の対象を絞れるようになったため、webhook が落ちていても他の Service は作成でき、クラスタブートストラップ時の循環依存も解消できる(有効化は values 側での設定が必要)。ほかに、ノードが Ready→NotReady→Ready と揺れた際にターゲット登録の遅延が pod の経過時間として観測されていた問題の修正と、セキュリティグループの ingress authorize/revoke 失敗が error レベルでログに出るようになった改善(従来は CloudTrail でしか追えず、共有バックエンド SG の失敗で複数の TargetGroupBinding の reconcile が止まる原因を特定しづらかった)が含まれる。NLB/ALB を Ingress から作っている構成ではセキュリティ修正目的で追随する価値がある。
