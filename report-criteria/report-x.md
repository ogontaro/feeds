# X タイムラインレポートの選定基準

`report-x-input.json` は X ホームタイムラインの過去24時間のポスト（`text` 本文、`link` ポスト URL、
`author` 投稿者ハンドル、`links` 本文中の外部 URL、`published`）。大半はエンジニアリングと無関係な
ポストなので、**エンジニアとして役に立つものだけ**を抜き出し、似た話題をトピックにまとめる。
該当が 0 件なら「本日の対象記事はありませんでした」とだけ書く。

このレポートは誰でも読める公開ページになる。迷ったら載せない。

## 採るもの

- AI コーディングエージェント（Claude Code / Codex / Cursor 等）の新機能・使い方・プラグイン・
  利用上限・料金・サブスク（月額 10 ドル前後のサブスク型サービスの提供開始・料金変更は必ず採る）
- LLM 全般・ローカル LLM（モデル、推論環境、GPU・ハードウェア）の実務に効く話
- Platform Engineering / Kubernetes / クラウド / SRE（イベント登壇・スライド・ブログの紹介を含む）
- セキュリティ（脆弱性、インシデント、サプライチェーン）
- 開発ツール・OSS のリリースや便利な使い方、技術記事・スライドの紹介

## 必ず除外するもの

- 技術と無関係なポスト（ゲーム、アイドル・芸能、食事、スポーツ、政治・時事、日常の近況など）。
  トピック名や「その他」欄でも触れない
- 個人の私生活・人間関係・私的なやり取り（リプライの応酬など）。技術的な中身があっても、
  特定の個人の事情を読み取れる形では書かない
- 宣伝・求人・イベント告知だけで技術的な中身がないもの、感想だけで情報がないもの

## まとめ方

- 同じ話題のポスト（同じリリース・同じ記事・同じ障害への言及）は 1 トピックにまとめ、関連ポストを並べる
- 要約は入力に書かれている事実だけで書く。推測で補わない
- 投稿者は URL 上のハンドル（`author`）でだけ示す。表示名や人物評は書かない

## 出力フォーマット（`.cache/report-x.md` に書く。このファイルだけ）

トピックを次のグループに分け、この順で `##` 見出しを立てる。該当が無いグループの見出しは出さない。

- `## AI コーディングエージェント（N 件）`
- `## LLM・ローカル LLM（N 件）`
- `## プラットフォーム・クラウド（N 件）`
- `## セキュリティ（N 件）`
- `## 開発ツール・その他技術（N 件）`

各トピックは次の形式で書く。

```
### <日本語のトピック見出し>
<2〜4文の日本語の要約。何が起きた/分かったか、なぜ役に立つかを書く。>
- [<author> のポスト](<link>)
- [リンク先を読む](<links の URL>)
```

- ポストが英語など日本語以外のときは、要約を日本語の概要として、ポストの行を
  `[<author> のポスト（原文）](<link>) / [Google 翻訳で読む](https://translate.google.com/translate?sl=auto&tl=ja&u=<URLエンコードした link>)` にする
- 外部リンクが海外（日本語以外）のページなら、その行を
  `[原文を読む](<URL>) / [Google 翻訳で全文を読む](https://translate.google.com/translate?sl=auto&tl=ja&u=<URLエンコードした URL>)` にする
- 外部リンクが無いポストは「リンク先を読む」の行を出さない
