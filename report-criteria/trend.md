# 月次トレンドレポートの判定基準

目的は、業界全体の**潮流の変化**を月単位で追うこと。「SRE から Platform Engineering / IDP が
出てきた」のように、新しい概念・呼称・開発方式が現れ、広まり、定着（または消滅）していく流れを捉える。
個別ツールのリリースや単発ニュースそのものは扱わない。それらは潮流の根拠としてだけ使う。

## 入力（`.cache/trend-input.md`）

大きいファイルなので、Read の offset/limit で分けて最後まで読むこと。

- `# 対象月`: YYYY-MM
- `## 前回のトレンドレポート`: 前回のレポート（HTML）。前月との差分を書くために使う。初回は「なし(初回)」
- `## 当月の日次レポート・週次リリース`: 見出しは `report|release / <ドメイン> / <日付>`。ドメインは claude / kubernetes / aws / devtools / gadget
- `## 外部情報源`: 当月に外部情報源が公開した記事。見出しの `[...]` が三角測量の種別

## 三角測量（判定）

根拠の種別は次の 3 つ。

| 種別 | 該当する入力 |
| --- | --- |
| 定量調査 | 外部情報源の `[定量調査]`（Stack Overflow / JetBrains / CNCF / Linux Foundation / State of Platform Engineering の調査結果） |
| 専門家判定 | 外部情報源の `[専門家判定]`（Thoughtworks Technology Radar・Insights、Martin Fowler） |
| 実活動データ | 外部情報源の `[実活動データ]`（GitHub Octoverse 等）と週次リリース（`release`）（実際のリリース・採用の動き） |

種別は**記事の中身**で決める。見出しの `[...]` はそのソースが出しがちな種別の目安にすぎない。

- 調査結果（回答者数・母数のある数値）を示す記事は、どのソース・日次レポートに載っていても**定量調査**に数える
  （例: `[実活動データ]` の GitHub Blog が載せた開発者調査、ニュースが報じた調査結果）
- 専門家の評価（Technology Radar、Fowler のサイトの論考）は**専門家判定**
- リポジトリ・利用の統計や、実際のリリースは**実活動データ**
- どれにも当たらない記事（製品告知・ポッドキャスト・解説など）は**補強材料**で、種別に数えない
- 要約の無い記事（タイトルと URL だけ）は中身を確かめられないので補強材料扱い

- 2 種別以上で確認できたもの → **トレンド**。前回のレポートで同じ概念に別の種別の根拠があれば合算してよい
  （調査は年に数回しか出ないため、月をまたいで揃ったら認定する）
- 1 種別のみ、または補強材料のみ → **シグナル**
- ベンダー記事の市場予測の数値は根拠にしない

## 書き方

- 項目の粒度は「概念・方式」（例: Platform Engineering、Spec-Driven Development）。製品名や単発の出来事にしない
- **系譜**（何から派生したか・何を置き換えるか）は、入力の記事がそう述べているときだけ書く。推測で書かない。無ければ行ごと省く
- 海外記事へのリンクは必ず三点セット（日本語の概要 + 原文 + Google 翻訳 URL）。日本語記事は原文リンクのみ。
  Google 翻訳 URL は `https://translate.google.com/translate?sl=auto&tl=ja&u=<URLエンコードした link>`
- リンクは入力にあるものだけを使い、作らない。各項目には判定の根拠にした記事のリンクを必ず含める

## 出力フォーマット（`.cache/trend.md` に書く。このファイルだけ）

```
## 前月からの変化

<前回取り上げた潮流が今月どうなったか（広がった・落ち着いた・言及が消えた）を 3〜6 行。初回はこの見出しごと省く>

## 今月の潮流

### <概念名>
**判定**: トレンド（<種別>＋<種別>） または シグナル（<種別 or 補強のみ>）
**系譜**: <派生元・置き換える対象> → <概念名>（根拠があるときだけ）
<2〜4 行の日本語。何が起きているか。前回も取り上げていれば何が変わったか。>
- <日本語の概要>: [原文](<link>) / [Google 翻訳で読む](<翻訳URL>)
```

- 「今月の潮流」は 3〜7 件。新しく出てきたもの、広がりが目立つものを優先する
