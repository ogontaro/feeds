# Kubernetes レポートの選定基準

`report-kubernetes-input.json`（過去24時間の新着、タイトルと概要は日本語化済み）から、
重要なものを **5〜10 件** 選ぶ。0 件なら「本日の対象記事はありませんでした」とだけ書く。

## 重視する軸

1. **関心領域との一致（主）**
   - Kubernetes 本体・CNCF プロジェクトの動向（Argo, Crossplane, cert-manager 等）
   - GitOps / IaC / プラットフォームエンジニアリングの設計・運用
   - セキュリティ、マルチテナンシー、スケーリング、コスト最適化
2. **実務への効き（従）** — 設計判断や運用に効くか、広く参照されそうか

## 除外するもの

- 求人・宣伝・イベント告知でエンジニアリング的な中身がないもの
- 同一トピックの重複（最も情報量が多い1本に絞る）
- 特定クラウドベンダー固有の話（AWS レポート側で扱う）

## 出力フォーマット（`.cache/report-kubernetes.md` に書く。このファイルだけ）

```
## 今日の N 本

### <日本語タイトル>
<2〜3文の日本語コメント。要約ではなく「なぜ読む価値があるか」を書く。>
[原文を読む](<link>) / [Google 翻訳で全文を読む](https://translate.google.com/translate?sl=auto&tl=ja&u=<URLエンコードした link>)
```

## 深掘りオプション

入力の中に同一トピックについて複数ソースから記事が集まっている日は、通常の複数選定に代えて、
そのトピック1本を深掘りする形式を選んでよい（広く浅くより、たまには1本をじっくり読みたい）。
その場合は上記の代わりに以下の形式で書く。

```
## 今日の深掘り: <トピック名>

<5〜8文の日本語コメント。複数ソースの内容を統合し、背景・論点・実務への影響を掘り下げる。>

- [ソース1を読む](<link1>)
- [ソース2を読む](<link2>)
```
